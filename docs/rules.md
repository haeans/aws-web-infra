| 번호 | 날짜 | 규칙 | 이유 |
|---|---|---|---|
| 1 | 2026-10-28 | 단계 폴더에는 README.md, images/, files/만 둔다. files/는 하위 폴더 없이 쓴다. 파트는 폴더가 아니라 README 섹션으로 나눈다. | 파트가 쌓여도 파일 위치가 일정해야 한다. 단계마다 파일 수가 적어 폴더를 나누면 깊이만 늘어난다. |
| 2 | 2026-10-28 | 파일 이름은 영문 소문자와 하이픈만 쓴다. 도구나 관례가 정한 이름은 그대로 쓴다. 캡처는 `p파트번호-내용.png`, 구성도는 `diagram-범위.png`, 스크립트는 `동사-대상.sh`로 짓는다. 날짜와 버전은 이름에 붙이지 않는다. | 리눅스는 대소문자를 구분한다. 공백은 명령어에서 이름을 쪼갠다. 한글은 터미널과 URL에서 깨질 수 있다. 버전 관리는 git이 맡는다. |
| 3 | 2026-10-28 | 커밋 메시지는 `타입: 핵심 내용 (#이슈번호)` 형식으로 쓴다. 타입은 feat, config, docs, fix 네 가지만 쓴다. 커밋 전에 GitHub 이슈를 먼저 만든다. Claude는 메시지를 추천만 하고, 커밋은 사용자가 직접 하거나 승인한 경우에만 한다. | 한 줄로 작업 구역과 핵심을 알 수 있어야 한다. 이슈 번호로 작업 단위를 추적한다. 커밋 같은 행동은 자동으로 하지 않고 사용자가 통제한다. |
